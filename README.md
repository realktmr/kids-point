# kids-point

子供の行動にポイントを付けて管理する、家庭向けの Web アプリです。
iPhone アプリ「Famipoi」の置き換えとして作りました（Famipoi は子供が自分のポイントを見られないため）。

## 概要

- **親のアカウント**（ID＋パスワード）と**子のアカウント**（名前を選んで4桁PIN）の2種類があります。
- 子は「やったよ申請」（プラスの項目を選んで申請）ができ、親が承認するとポイントが付きます。
- 親は、項目を使わずに点数と理由を手入力して直接ポイントを付けることもできます（マイナスも可＝減点）。
- ポイントは現金に交換できます。子が「つかう申請」をし、親が承認して現金を渡します。ポイントと円のレート（例: 1ポイント=1円）は親が設定します。
- 他のアプリ（Famipoi など）からの残高の引き継ぎ用に、「繰越」という特別な記録も付けられます（詳細は [使い方](#使い方) を参照）。
- 今の残高と、1か月分のカレンダー（日ごとの `+xx` / `-xx` / 利用 / 繰越、月の合計）を見られます。
- 子ができるのは、自分のポイントの閲覧と、やったよ申請・つかう申請・自分の申請の取り下げだけです。それ以外の操作や、他の子のデータには一切触れません。

### 構成

とにかくシンプルに作ってあります。

- 画面: `public/index.html` 1枚 ＋ `public/app.js`（フレームワーク無しの素の JavaScript）＋ `public/style.css`
- サーバ側: `public/api.php` 1本（共通処理は `src/` 以下の PHP クラスに分けてあります）
- データ: `data/kids-point.json` 1ファイル（データベースは使いません）
- 最初の親アカウント作成用の CLI: `bin/create-parent.php`
- 試験: `tests/run.sh`

```
public/          ← Web に公開するのはここだけ
  index.html  app.js  style.css  manifest.json  apple-touch-icon.png
  api.php
src/             ← api.php が require する共通クラス
bin/create-parent.php
data/            ← git 管理外。Web に公開しない
tests/run.sh
```

## 動作環境

- **PHP 8.1 以上**
  （`never` 戻り値型・コンストラクタプロパティ昇格＋`readonly` を使っているため、8.1 未満では動きません）
- 必要な PHP 拡張
  - **mbstring**（名前やメモなどの文字数を数えるのに使用。ディストリビューションによっては別パッケージなので、入っていなければ入れてください。例: Debian/Ubuntu 系なら `php8.1-mbstring` のようなパッケージ）
  - **session**（ログインのセッション管理。PHP 本体に含まれます）
  - **json**（PHP 8 以降は本体に含まれ、通常は別途インストール不要です）
  - **hash**（保持トークンのハッシュ化などに使用。PHP 本体に含まれます）
- PHP が動く Web サーバ（以下は Apache + mod_php または PHP-FPM を想定した例です）
- **HTTPS が必須です**。セッション cookie・保持 cookie に Secure 属性を付けており、HTTP では送られません（ローカルでの試験時だけ、環境変数で外せます。[開発とテスト](#開発とテスト) を参照）

## セットアップ（Apache の例）

以下は一例です（`/var/www/kids-point` に clone し、`https://例のドメイン/kids-point/` で公開する場合）。

### 1. 公開ディレクトリの外に clone する

```sh
sudo mkdir -p /var/www/kids-point
sudo chown "$USER": /var/www/kids-point
git clone https://github.com/realktmr/kids-point.git /var/www/kids-point
```

このリポジトリは public なので、認証情報なしで clone できます。
clone したディレクトリは、ふだん使う一般ユーザーの持ち物にしておきます（更新の `git pull` もこのユーザーで行います）。Web サーバのユーザーが書き込むのは `data/` だけです。

### 2. data/ を作り、Web サーバのユーザーだけが読み書きできるようにする

```sh
sudo mkdir -p /var/www/kids-point/data
sudo chown -R www-data:www-data /var/www/kids-point/data
sudo chmod 700 /var/www/kids-point/data
```

（`www-data` は Debian/Ubuntu 系 Apache の実行ユーザーの例です。環境によって異なります）
`data/backup/` サブディレクトリは、アプリが初回起動時に自動で作ります（パーミッション `0770`）。

### 3. public/ だけを公開する

**方法A: ドキュメントルートから public/ へのシンボリックリンク**（本プロジェクトの想定運用）

```sh
sudo ln -s /var/www/kids-point/public /var/www/html/kids-point
```

Apache 側の `DocumentRoot` が `/var/www/html` で、`FollowSymLinks`（または `+SymLinksIfOwnerMatch`）が有効なら、これだけで `https://例のドメイン/kids-point/` から `public/` の中身だけが見えます。`src/`・`data/`・`bin/` は一切公開されません。

**方法B: Alias を使う**

```apacheconf
Alias /kids-point /var/www/kids-point/public
<Directory /var/www/kids-point/public>
    Require all granted
</Directory>
```

どちらの方法でも、`Indexes` を無効にしておくこと（ディレクトリ一覧が見えないように）と、`public/` の中にサブディレクトリを作らないこと（このリポジトリのコードはその前提で動いています）を守ってください。

設定を変えたら構文を確認してから反映します。

```sh
sudo apache2ctl configtest
sudo systemctl reload apache2
```

### 4. 最初の親アカウントを作る

```sh
sudo -u www-data php /var/www/kids-point/bin/create-parent.php
```

- **Web サーバの実行ユーザー（例: `www-data`）で実行してください。** そうしないと、後で `api.php`（Web サーバのユーザーで動く）が `data/kids-point.json` を読み書きできず、パーミッションエラーになります。
- パスワードは、入力中の文字が画面に表示されません（`stty -echo` で端末のエコーを止めています）。
- **この作成コマンドは CLI 専用です。** `bin/create-parent.php` は `PHP_SAPI !== 'cli'` を確認しており、Web からアクセスしても 403 を返すだけで何も作られません（そもそも `public/` の外にあるので通常は Web からは辿り着けません）。最初の親アカウントを Web 経由の API で作れるようにしてしまうと、公開直後に誰かに先を越されて他人が親アカウントを作れてしまうため、意図的にサーバ上のコマンドだけに限定しています。

### 5. ログイン後の初期設定

1. 作成した親アカウントでログインします。
2. 「アカウントの管理」から、子供を追加します（名前・色・4桁PIN）。Famipoi など他アプリから残高を引き継ぐ場合は、同じ画面の「引き継ぎポイント」欄に今の残高を入れると、子供の作成と同時に繰越の記録が1件作られます。
3. 「項目の管理」から、ポイントの項目（例: 「テスト100点」= +100P、「片付けができなかった」= -10P）を登録します。
4. 「レート設定」から、ポイントと現金のレート（例: 1ポイント=1円）を設定します（初期値は 1P=1円）。

### 6. 公開パスを /kids-point/ 以外に変えるとき

コードが読む環境変数は次のとおりです。Web サーバの起動設定（例: `/etc/apache2/envvars` や、PHP-FPM プールの `env[...]`）で渡してください。

| 環境変数 | 既定値 | 意味 |
|---|---|---|
| `KIDS_POINT_DATA_DIR` | `realpath(public/../data)` | データファイルの置き場所。`public/` からの相対ではなく絶対パスで指定する運用にする場合に使う |
| `KIDS_POINT_COOKIE_PATH` | `/kids-point/` | セッション cookie（`KPSESSID`）と保持 cookie（`kp_remember`）の `path` 属性。公開パスを変えたら、ここも同じ値に合わせる |
| `KIDS_POINT_INSECURE_COOKIES` | 未設定（＝Secure 属性あり） | `1` を設定すると cookie の Secure 属性を外す。**HTTP で動かすローカル試験専用**。本番では絶対に設定しないこと |

**注意（未確認）**: Apache の `SetEnv` で渡した環境変数が PHP の `getenv()` から見えるかどうかは、SAPI（mod_php か PHP-FPM か）や PHP・Apache のバージョンによって挙動が分かれることが知られており、**`SetEnv` 経由の値が実際に `getenv()` に渡ることは確認していません**。確実な方法は次のどちらかです。

- PHP-FPM を使っている場合は、プール設定の `env[KIDS_POINT_COOKIE_PATH] = /xxx/` を使う（`getenv()` から確実に見える）
- mod_php の場合は、Apache の起動スクリプトのシステム環境変数（`/etc/apache2/envvars` に `export KIDS_POINT_COOKIE_PATH=/xxx/` を追記するなど）として設定する

導入時は、設定後に実際に `getenv()` の値が反映されているか（例えば一時的に `phpinfo()` やログで確認する）を必ず確かめてください。

### 7. data/ が Web から見えないことの確認

```sh
curl -I https://例のドメイン/kids-point/data/kids-point.json
```

`data/` は `public/` の外にあるため、公開ディレクトリからは存在しないパスです。**404**（Alias 方式）または、そもそもドキュメントルートの外なので **403 / 404** が返ることを確認してください。200 が返る場合は、公開ディレクトリの設定が誤っています（`public/` 以外まで公開してしまっている可能性）。

## 更新とバックアップ

- 更新は `git pull` だけです（DB を使っていないので、マイグレーションはありません）。

  ```sh
  cd /var/www/kids-point
  git pull    # clone したユーザーで実行する
  ```

- 全データは `data/kids-point.json` 1ファイルにまとまっています。
- 書き込みのたび（1日の最初の書き込みの前）に、書き換える前の状態が `data/backup/YYYY-MM-DD.json` として残ります。**60日より古いバックアップは自動で削除されます。**
- 復元するときは、サーバを止める必要はありません（`api.php` はファイルの排他制御をしていますが、念のため利用が少ない時間帯に行うことをおすすめします）。

  ```sh
  sudo cp /var/www/kids-point/data/backup/2026-09-01.json /var/www/kids-point/data/kids-point.json
  sudo chown www-data:www-data /var/www/kids-point/data/kids-point.json
  ```

## 使い方

### 子の操作

- 名前を選んで4桁PINでログインします。
- **ホーム**: 今の残高（円換算も表示）と、今月のカレンダーが見られます。日付をタップするとその日の明細が出ます。
- **やったよ申請**: プラスの項目を選び、行った日（今日から60日前まで）とひとことメモを付けて申請します。
- **つかう申請**: 使いたいポイントを入れて申請します。円換算額もその場で表示されます。申請できるのは「承認済みの残高 − 今申請中の利用分」までです。
- **申請一覧**: 自分の申請（申請中・承認・却下・取り消し）が見られます。申請中のものは、ここから取り下げられます。

### 親の操作

- ID とパスワードでログインします。
- **承認待ち**: やったよ申請・つかう申請を1件ずつ承認・却下します。つかう申請を承認した時点で「現金を渡した」ことにします（実際に現金を渡してから承認してください）。
- **カレンダー**: 子供を切り替えて、その子のカレンダー・残高を見られます。
- **検索**: キーワード（例:「実力テスト」）と子供（任意）で過去の記録を検索します。項目名・メモ・却下理由のいずれかに、入れたキーワードすべてを含む記録（AND検索）が、行った日の新しい順に出ます。見つかった件数と承認済みポイントの合計も表示されます。全角/半角・大文字/小文字・半角カナ/全角カナの違いは区別しません。
- **直接付ける**: 項目を選ぶか、点数と理由を手入力してポイントを直接付けます（マイナス＝減点も可）。手入力のときだけ「引き継ぎ（繰越）として付ける」を選べます。
- **取り消し**: 誤って付けた記録（承認済みのもの）を取り消せます。取り消した人と日時が記録に残ります。
- **項目の管理**: 項目の追加・編集・使わなくする・並び替えができます。項目の点数を後で変えても、すでに付いた記録は変わりません（記録した時点の値を保持しています）。
- **レート設定**: ポイントと現金のレート（X ポイント = Y 円）を設定します。
- **アカウントの管理**: 子供（名前・色・PIN の再設定・有効/無効）と、親（複数可、パスワードの再設定）を管理します。子供を追加するときに「引き継ぎポイント」を入れると、その場で繰越の記録が1件作られます。

### 「繰越」について

Famipoi など他のアプリからの残高を移すための、特別な記録です。

- 残高には反映されますが、カレンダーの「もらった」「減った」「使った」のどれにも数えません。日ごとのマスには `↺ 繰越 +1000` のように別の印と色で出ます。月のまとめにも「繰越」として別行で出ます。
- 作れるのは親だけです。子は作れません。
- 作り方は2通りあります。①子供を追加するときに「引き継ぎポイント」欄へ入力する、②「直接付ける」画面で「引き継ぎ（繰越）として付ける」にチェックを入れて手入力する（項目から選んだときは使えません）。
- ほかの記録と同じように、親は「取り消し」で取り消せます。

### iPhone のホーム画面に追加する

1. Safari で `https://例のドメイン/kids-point/` を開きます。
2. 共有ボタン（四角から上に矢印が出ているアイコン）をタップします。
3. 「ホーム画面に追加」を選びます。

ホーム画面から開いたときは、通常の Safari とは cookie が別になります。そのため、初回はログインが必要ですが、ログインは30日間保持されます（[セキュリティについて](#セキュリティについて) を参照）。

### ポイント利用の流れ

1. 子が「つかう申請」で使いたいポイントを申請します。
2. 親が「承認待ち」画面で内容（円換算額）を確認し、**実際に現金を渡してから**「承認」を押します。
3. 承認した時点でポイントが減り、その日が利用日として記録されます。

## セキュリティについて

- **PIN のロック**: 子の4桁PINは総当たりされやすいため、多重にロックします。
  - 子ごとに、15分間に5回間違えるとその子は15分間ロックされます。
  - 接続元 IP ごとに、15分間に20回間違えるとその IP からのログインが15分間ロックされます。
  - 親のログインIDごとにも、15分間に5回間違えると15分間ロックされます。
  - ロック中は、正しい PIN・パスワードを入れてもログインできません。
  - 存在しない子・存在しないログインIDへの試行は、IP のロックにのみ数えます（際限なくロック用の記録が増えるのを防ぐため）。期限が切れた記録は、ログイン処理のたびに自動で掃除されます。
- **CSRF**: 状態を変える操作（POST）はすべて、セッションに紐づく CSRF トークンをヘッダーで送る必要があります。トークンが無い・間違っている場合は 403 になります。セッションが切れた直後の1回だけは、画面側が自動でトークンを取り直して再送します。
- **ログインの30日保持**: `kp_remember` という cookie に、30日間有効な保持トークンを持たせます。データには SHA-256 のハッシュと期限だけを保存し、平文のトークンは保存しません。使うたびに新しいトークンへ差し替えます（差し替え直後60秒だけ、同時アクセスの取りこぼしを防ぐための猶予があります）。ログアウト・PIN やパスワードの変更時には、その人の保持トークンをすべて無効化します。
- **秘密情報を持たない構成**: データベースのパスワードのような秘密情報がそもそも要らない作りです。パスワードと PIN は `password_hash`/`password_verify` でハッシュ化して保存し、API のレスポンスにハッシュや保持トークンが出ることはありません。親のパスワードは **12文字以上** を必須にしています。
- **子の権限は最小限**: 4桁PINは1万通りしかなく破られる可能性がゼロではないため、子にできることを「自分の残高・カレンダー・明細・申請一覧の閲覧」「やったよ申請」「つかう申請」「自分の申請中のものの取り下げ」だけに限定しています。それ以外の操作（項目の管理、直接付ける、承認、他の子のデータの閲覧など）は、サーバ側ですべて 403 になります。無効化されたアカウントは、セッションが残っていてもすぐにログアウト扱いになります。
- **検索エンジンに載せない**: `index.html` に `<meta name="robots" content="noindex, nofollow">`、`api.php` のレスポンスに `X-Robots-Tag: noindex, nofollow` ヘッダーを付け、検索結果に出ないようにしています。
- リポジトリは public です。実データ（子供の実名・PIN・記録）は `data/` に git 管理外で保存され、コミットには含まれません。

## 開発とテスト

### ローカルで動かす

PHP 8.1 以上と mbstring 拡張が入っていれば、追加のインストールなしで動かせます（DB 不要）。

```sh
export KIDS_POINT_DATA_DIR=/tmp/kids-point-data   # 好きな一時ディレクトリ
export KIDS_POINT_INSECURE_COOKIES=1              # HTTPでも cookie を送れるようにする（ローカル専用）
export KIDS_POINT_COOKIE_PATH=/                   # ドキュメントルート直下で試すときはこれに合わせる
php -S 127.0.0.1:8080 -t public
```

別のターミナルで最初の親アカウントを作ります。

```sh
php bin/create-parent.php
```

ブラウザで `http://127.0.0.1:8080/` を開けば動作を確認できます。

### 自動テスト

```sh
bash tests/run.sh
```

一時データディレクトリを作り、`php -S`（4ワーカー）を自動で起動・停止しながら、権限・CSRF・PINロック・残高とカレンダーの集計・利用申請の上限・同時書き込みなど一式を検証します。`php -l` と `node --check public/app.js` も同じスクリプトの中で実行します。1コマンドで完結し、失敗すると終了コードが0以外になります。
